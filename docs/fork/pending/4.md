## keys

One binding for `src/fork/keys.ts`:

```ts
  // Esc leaves the search list (4.3). Upstream's Escape case runs first for
  // a ticked selection and an open thread, so this fires on the third Esc
  // at most and never steals the first one.
  if (e.key === "Escape" && mail.searching && !mail.selecting && mail.selectedThreadId === null) {
    e.preventDefault();
    void mail.exitSearch();
    return true;
  }
```

Guard reasoning: `forkKey` runs before upstream's switch, so without the two
extra conditions the first Esc would close the search under an open thread.
Optional `ShortcutsOverlay.svelte` rows: `Shift ↵` (in the palette) →
`fork.shortcuts.search_list`, `Esc` → `fork.shortcuts.search_close`.

## DECISIONS

- **2026-09-23 D-4a (4.3): the store's `refreshFolders` got a one-line guard.**
  `refreshFolders` replaces `state.folders` on every `folders:updated` and
  auto-selects the inbox when `selectedFolderId` is not in the new list. The
  search folder (-900) never is, so every sync would have bounced the user out
  of their search. Alternatives (a synthetic folder row in `state.folders`,
  or keeping `selectedFolderId` on the old folder and branching on the query)
  both leaked into the sidebar or broke sidebar clicks. The guard is marked
  `Fork (4.3)` and is the one upstream line touched outside the fork section.
- **2026-09-23 D-4b (4.1): `in:starred` is the star flag, not the Gmail
  Starred folder.** `m.is_starred = 1` in any folder; that is what a starred
  search means for IMAP and Gmail alike. `in:spam` maps to role `junk`,
  `in:anywhere|all|any` lifts the default Trash/Spam exclusion, any other
  value is a label matched by display name (case-insensitive).
- **2026-09-23 D-4c (4.1): `-word` is an FTS subquery, not a LIKE.**
  `m.id NOT IN (SELECT rowid FROM messages_fts WHERE messages_fts MATCH ?)`
  so a negated word works with or without positive text and
  `build_fts_query` stays the only place that builds a MATCH string for the
  positive terms. `-from:` / `-to:` / `-cc:` / `-subject:` negate their
  clause; `-is:unread` reads as `is:read`; `-in:`, `-before:` etc. stay free
  text.
- **2026-09-23 D-4d (4.3): search results are always grouped by thread**,
  whatever `group_threads` says: the command is `fork_search_threads` and
  rows carry `messageId: null`, exactly as `list_threads` does. Each row is
  shaped by its newest *matching* message; unread and attachment state read
  over the whole thread, like the list. `older_than:Nm` = 30 days, `Ny` =
  365 days; the tighter of two bounds wins.
- **2026-09-23 D-4e (4.3): chips are tokens, not a second parser.**
  `src/fork/search/query.ts` only splits the typed string (quote-aware) and
  recognises operator tokens; removing a chip drops that token and re-runs
  the search through Rust, which owns the semantics.
- **2026-09-23 D-4f (4.3): "no row highlighted" is `active === -1`.** The
  palette always highlighted row 0, so plain Enter had no way to mean "show
  the list". ArrowUp from the first row now clears the highlight (only while
  a query is typed); Enter then, with nothing to highlight, or with Shift,
  shows the results in the list. A `⇧ ↵ list` hint sits by the input.
- **2026-09-23 D-4g (4.3): the search scope is the active mailbox** (every
  mailbox in the unified view), the same scope the palette's inline hits use.
