A window that regains focus should refresh whichever of Sent/Drafts is open
(Rust debounces to once per 20 s per folder, so a focus flurry is free).
Two lines in the script block, one in the existing mount/cleanup:

    import { windowFocused } from "./fork/freshness";

Inside the existing `onMount` (or `$effect`) that registers window listeners:

    window.addEventListener("focus", windowFocused);
    return () => window.removeEventListener("focus", windowFocused);

Optional: if the shell already listens to `window:shown` (the tray restore
event, see `mail.svelte.ts` `attachListeners`), also call `windowFocused()`
from that handler, because a webview shown from the tray does not always fire
DOM `focus`. Either call is safe: `windowFocused()` is a no-op unless the
current folder's role is `sent` or `drafts`.

## DECISIONS

- **2026-09-23 D-3.4a:** `send` resyncs Drafts as well as Sent. Sending removes the
  server draft (`remove_server_draft`), so the Drafts folder changed on the server
  too; before this the local Drafts list kept the sent draft's row until the poll.
  `rsvp` resyncs Sent (it mirrors like a send). `roles_after_op` in
  `fork/freshness.rs` is the one table.
- **2026-09-23 D-3.4b:** `mirror_to_sent`'s Gmail branch already looked up the
  `sent` role id after its 1.5 s sleep, so Gmail was not entirely missing the
  resync; the plan's premise was half right. The sleep is left in place (Gmail
  files the copy asynchronously and a resync before it lands sees nothing); the
  role lookup is now done once, uniformly, in the drain via `folders_after_op`,
  so a future edit to `mirror_to_sent` cannot lose it.
- **2026-09-23 D-3.4c:** `fork_sync_folder` accepts any real folder id, not only
  Sent/Drafts; the UI (`src/fork/freshness.ts`) is what restricts to those two
  roles. The debounce (20 s per folder, `std::sync::Mutex<HashMap<i64, Instant>>`
  in a `OnceLock`, process-wide) bounds the cost whatever calls it. A refused
  request is dropped, not queued: the sync it wanted just ran or is queued.
- **2026-09-23 D-3.4d:** the targeted sync drains the op queue first (like
  `SyncInbox`), then skips the folder if the drain already resynced it, so
  opening Drafts right after a save costs one folder sync, not two. `drain_ops`
  now returns the set it resynced; the three existing callers ignore it.
- **2026-09-23 D-3.4e:** `windowFocused()` reuses the folder recorded by the last
  `folderSelected()` call instead of importing the mail store (no import cycle
  between `stores/mail.svelte.ts` and `fork/freshness.ts`).
- **2026-09-23 D-3.4f:** the `mail.svelte.ts` touch is two lines (the import and
  the call), not one: the import is unavoidable.
