## DECISIONS

- **2026-09-23 D22 (7.2):** `resolve_email` matches the required scope as a whole
  token (`scope.split_whitespace().any(==)`) instead of substring `contains`.
  Stricter, correct for space-separated scope lists; the mail scope still passes.
- **2026-09-23 D23 (7.3):** all three tables use `CREATE TABLE IF NOT EXISTS`
  so the fork runner's re-run (the `f0001_and_f0002_repair_live_rows` test
  deletes the version row and migrates again) is idempotent.
- **2026-09-23 D24 (7.4):** engine registry is a process-wide
  `OnceLock<Mutex<HashMap<account_id, CalHandle>>>` in `fork::calendar`
  (`handle()`, `spawn()`, `stop()`, `start_all()`, `on_window_focus()`), not a
  `ForkState` field, so the module does not depend on the struct the main
  session owns. Same for `fork::google::state()`.
- **2026-09-23 D25 (7.4):** window replace = upsert the fresh rows, then delete
  non-`local_only` rows in the window whose `google_id` was not returned. Row
  ids stay stable across pulls (the UI keys on them); a plain delete-then-insert
  renumbered every event every five minutes.
- **2026-09-23 D26 (7.4):** ops reference the local **row id** (`event_id`) and
  resolve the Google id at execution time, so a patch/RSVP queued behind a
  not-yet-landed create waits (non-transient `gcal_op` error, retried up to 5
  times) instead of sending a placeholder id. A delete of a row whose create
  never left the machine just drops its pending ops. A create that fails 5
  times drops its optimistic row.
- **2026-09-23 D27 (7.4):** `fork_cal_rsvp` also takes `send_updates`
  ("never implicit" applies to the RSVP notification to the organiser too).
  All-day rows store `start_ts`/`end_ts` as UTC midnights of the dates (a
  convention for ordering and the index); availability expands them to local
  days in the walking zone.
- **2026-09-23 D28 (7.2):** the account-mismatch error (`gcal_account_mismatch`)
  names the Google address the browser used and the mailbox address; nothing
  is stored.
- **2026-09-23 D29 (8):** `fork_free_slots` takes the walking zone `tz` (IANA)
  from the UI (`Intl.DateTimeFormat().resolvedOptions().timeZone`) rather than
  guessing the system zone from Rust (chrono-tz has no "local" lookup without
  a new dependency). Slot ends are instant arithmetic (`start + duration`), so
  a slot straddling a DST gap still lasts the duration; a start inside the gap
  is skipped.
