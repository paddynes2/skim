## DECISIONS

- **2026-09-23 D-9a (workspaces):** `GET /api/v1/workspaces` in Rebound is
  cookie-session only (`workspaces/route.ts` builds `createServerClient` from
  `cookies()` and calls `auth.getUser()` with no token; it never reads the
  `Authorization` header), so the plan's "Bearer to the route" step returns 401.
  `list_workspaces` tries the route first (in case that changes) and then runs
  the same membership query the route runs, straight against PostgREST:
  `GET {supabase}/rest/v1/workspace_memberships?select=role,workspace:workspaces(id,name,slug)&user_id=eq.<uid>`
  with `apikey` + Bearer, which the JWT and RLS scope exactly as the route
  would. Both shapes parse into one `Workspace` (tested).
- **2026-09-23 D-9b (stage names):** the lookup route returns deals as
  `{id, name, value, status, stage_id}` (no stage name). After a lookup with
  deals, Rust reads `pipeline_stages?select=id,name&id=in.(...)` through
  PostgREST, best effort, and fills `stage_name`. If that read fails the drawer
  shows the deal's status ("Open"). Still read-only.
- **2026-09-23 D-9c (reminders):** the route returns no reminders today. The
  struct carries `reminders: Option<Vec<Reminder>>` (`None` when absent), the
  drawer renders the section only when present, so the day the route adds
  them nothing changes on this side.
- **2026-09-23 D-9d (`fork_crm_set_config`):** one command more than the plan
  listed, because the Settings screen has editable URL/key fields and they
  need a writer. `None` leaves a field, `""` resets it to the build-time
  default (the form sends `None` for the anon key unless retyped, since it
  only ever shows it masked).
- **2026-09-23 D-9e (status and the network):** `fork_crm_status` is local
  (settings + "is there a refresh token") except when connected with no
  workspace chosen, where it lists workspaces for the picker; a failure there
  lands in `status.error`, never an exception, so Settings always renders.
  `fork_crm_connect` also lists them and auto-picks a sole workspace.
- **2026-09-23 D-9f (dead refresh token):** a `crm_auth` answer to a refresh
  means the token was revoked or rotated elsewhere; the module deletes
  `fork:rebound` and reports `crm_not_connected`, so status stops claiming a
  connection that cannot work and the drawer shows "Connect".
- **2026-09-23 D-9g (wire shape):** structs deserialise Rebound's snake_case
  columns and serialise camelCase to the UI (`rename_all(serialize)`), every
  field `Option` + `#[serde(default)]`, unknown fields ignored, so a column
  Rebound adds or drops never blanks the drawer (tested both ways).
- **2026-09-23 D-9h (address source):** the reading pane owns the focused
  message, so it reports the sender to `crmFocus` (one effect) and App passes
  `crmFocus.email` down; the drawer never imports the mail store.
