## App.svelte

Nothing in `App.svelte` itself. For the fork settings panel
(`src/fork/SettingsFork.svelte`), a section after Calendar/CRM:

    <script lang="ts">
      import { invoke } from "@tauri-apps/api/core";
      type McpStatus = {
        enabled: boolean; listening: boolean; port: number; endpoint: string;
        token: string | null; addCommand: string | null;
      };
      let mcp = $state<McpStatus | null>(null);
      let copied = $state(false);
      async function loadMcp() { mcp = await invoke<McpStatus>("fork_mcp_status"); }
      async function toggleMcp(on: boolean) {
        mcp = await invoke<McpStatus>("fork_mcp_set_enabled", { on });
      }
      async function copyMcp() {
        if (!mcp?.addCommand) return;
        await navigator.clipboard.writeText(mcp.addCommand);
        copied = true; setTimeout(() => (copied = false), 1500);
      }
      $effect(() => { loadMcp(); });
    </script>

    <section class="group">
      <h3>{t("fork.mcp.title")}</h3>
      <label class="row">
        <input type="checkbox" checked={mcp?.enabled ?? true}
               onchange={(e) => toggleMcp((e.target as HTMLInputElement).checked)} />
        <span>{t("fork.mcp.enable")}</span>
      </label>
      <p class="hint">{t("fork.mcp.hint")}</p>
      {#if mcp}
        <p class="status">
          {mcp.listening ? t("fork.mcp.listening", { port: mcp.port })
                         : (mcp.enabled ? t("fork.mcp.port_busy", { port: mcp.port })
                                        : t("fork.mcp.stopped"))}
        </p>
        {#if mcp.addCommand}
          <p class="hint">{t("fork.mcp.register")}</p>
          <pre class="cmd"><code>{mcp.addCommand}</code></pre>
          <button type="button" onclick={copyMcp}>
            {copied ? t("fork.mcp.copied") : t("fork.mcp.copy")}

          <p class="hint">{t("fork.mcp.token_note")}</p>
        {/if}
      {/if}
    </section>

## DECISIONS

- **2026-09-23 D-12a (transport):** the MCP server is hand-rolled (JSON-RPC 2.0
  over a ~120-line HTTP/1.1 reader on `tokio::net::TcpListener`), not `rmcp`.
  Checked `rmcp` 3.4.0 (crates.io, 2026-09-15) and its `Cargo.toml`: the
  `transport-streamable-http-server` feature yields a `tower::Service` over
  `http::Request` and ships **no HTTP server**; driving it needs `hyper` with its
  `server` feature (the lock only has hyper `client`/`http1` via reqwest),
  `http` and `http-body-util` as direct dependencies (not permitted), and it
  pulls `rmcp-macros`, `schemars` (chrono04), `sse-stream`, `rand 0.10`,
  `async-trait`, `pastey`. No TLS is dragged in either way, so that was not the
  blocker; the missing server was. Result: **no `Cargo.toml` change at all**
  and nothing added to the binary. Coverage: `initialize` (echoes 2024-11-05 /
  2025-03-26 / 2025-06-18, else answers 2025-06-18), `ping`, `tools/list`,
  `tools/call`, notifications → 202, batches, JSON-RPC error codes. Every POST
  is answered with `application/json` (the spec's non-streaming form);
  `GET /mcp` is 405 (no server-initiated stream) and `DELETE` 405 (no
  sessions, so no `Mcp-Session-Id` is ever issued). Verified against the MCP
  TS SDK's client expectations on paper only: the live check is the Phase 13
  smoke test (`search_mail` from Claude Code).
- **2026-09-23 D-12b (auth):** token = 32 random bytes as 64 hex chars (not
  base64url, so it is shell-safe inside the quoted header); compared in
  constant time; `401` + `WWW-Authenticate: Bearer` without it. A non-loopback
  peer gets `403` before anything is read; a non-localhost `Origin` header gets
  `403` (DNS-rebinding guard; Claude Code sends no Origin). One request per
  connection (`Connection: close`), which is what keeps the parser tiny; the
  cost is a loopback TCP handshake per call.
- **2026-09-23 D-12c (tools shape):** every tool result is a JSON object,
  returned both as `structuredContent` and pretty-printed `content[0].text`.
  Bad arguments and "not found" are tool results with `isError: true` (the
  model can recover); an unknown tool is a JSON-RPC `-32602`. `get_thread`
  bodies are capped at 20,000 chars each; `strip_quotes` falls back to the full
  text when the cut leaves nothing (bottom-posted replies).
- **2026-09-23 D-12d (create_draft):** a new draft needs `to` and `subject`; a
  reply (`reply_to_message_id`) defaults both from the original (`Re:` +
  sender). The account signature is appended like the composer does. The draft
  is then saved exactly as `save_server_draft` does (stable `imap_message_id`
  + `save_draft` op). The composer's quoted-original block is **not** appended
  (the model writes the whole body); upstream's send path still adds
  `In-Reply-To`/`References` from `reply_to_message_id` when Patrick sends.
- **2026-09-23 D-12e (create_event):** lands on the selected primary calendar
  of the first account (else the first selected calendar), `send_updates:
  none`, `attendees: None`, no Meet; the test asserts the queued body has no
  `attendees` key. `google::is_connected` is not re-checked here: a calendar
  row only exists after a connect, and the op fails safely later if the grant
  went away.
- **2026-09-23 D-12g (test binary vs the wry runtime; READ BEFORE ADDING
  TESTS THAT TOUCH `AppHandle`):** the first version of the tools called
  `app.emit` / `app.state` / `badge::refresh` directly, and every test in the
  crate then died at load with `STATUS_ENTRYPOINT_NOT_FOUND` (0xC0000139),
  including tests that never ran a server. Cause, found by diffing the PE
  import tables of the old and new test binaries with `pefile`: any code path
  that reaches the wry runtime links `comctl32!TaskDialogIndirect`
  (`tauri-runtime-wry/src/dialog/windows.rs`), which exists only in Common
  Controls v6, which needs the application manifest `tauri-build` embeds for
  the **bin** target only; the `cargo test` binary has no manifest, so the
  loader refuses it before `main`. Until now nothing test-reachable had named
  an `AppHandle` method. Fix: the app-side effects live behind
  `fork::mcp::Hooks` (a trait object: `mail_changed`, `drafts_changed`,
  `calendar_changed`, `crm_lookup`); `AppHooks(AppHandle)` implements it and
  is referenced only from `launch`, which no test reaches, so the linker
  drops the runtime from the test binary. Rule for later phases: a test must
  not be able to reach `AppHandle`/`Emitter`/`Manager` methods, or the whole
  suite goes red at load; inject a hook instead.
- **2026-09-23 D-12f (fork_mcp toggle):** `fork_mcp_set_enabled` binds/stops at
  once (std bind on the caller's thread so `listening` is true on return, then
  the listener is handed to the runtime). `fork_mcp_status` reports `token:
  null` until the server has run once with the setting on.
