## DECISIONS

- **2026-09-23 D-5a (5.3, fold CSS):** the fold rule uses `display: none !important`. Outlook's reply header is followed by `<hr style="display:inline-block;width:98%">`; an inline style outranks a plain stylesheet rule, so without the flag a stray rule stayed visible under every folded Outlook reply (caught in the render check). Mail's own `!important` never reaches the viewer (`filter_style` strips the flag), so this cannot be countered from the wire.
- **2026-09-23 D-5b (5.3, "whole body is a forward"):** the default-unfolded exception is decided in the pane as "thread has one message AND subject starts with Fwd/FW/WG/TR". A lone forward with nothing said above the header already has `hasFold: false` (no visible content above the marker) and shows no pill; the subject rule covers the case where a line ("FYI") sits above the forwarded header.
- **2026-09-23 D-5c (5.2, interleaved replies):** a run of `>` lines is a fold point only when every line from it to the next hard marker (or the end) is quoted or blank. An interleaved reply (quote, answer, quote, answer) is therefore never folded at its first quote; `strip_quoted` is not changed.
- **2026-09-23 D-5d (5.1, class precedence):** a div carrying both a signature and a quote class (`gmail_signature gmail_quote`) becomes `skim-quote`; both are hidden when folded, and the quote class is the one that says where the tail starts.
- **2026-09-23 D-5e (5.3, `has_fold` scope):** `has_fold` matches any `type="cite"` blockquote, while the stylesheet hides only top-level ones (`body > blockquote`, `body > div > blockquote`). A deeply nested cite blockquote above any other marker could yield a pill that toggles nothing visible. Left as is: every real client wraps the cite blockquote in a `skim-quote` div or places it at the top level, and the sanitizer emits nothing else that matches.
- **2026-09-23 D-5f (5.3, toggle mechanics):** toggling rebuilds `srcdoc` (the fold CSS is part of `buildDoc`), so the iframe reloads and the existing poll + ResizeObserver re-measure the height. No live DOM mutation of the iframe document.
